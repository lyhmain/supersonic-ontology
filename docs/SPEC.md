# 规范配置(Standard Spec)—— 普通数据开发接入指南

> 不想理解本体?只需要填一张**中文四清单**(主表/维度/指标/验收),其余全自动。
> 控制台 → 接入向导 → 顶部"标准配置"卡片,粘贴保存即可。

## 最小示例(连锁茶饮,可直接跑通)

```json
{
  "profile": "tea",
  "业务说明": "连锁茶饮",
  "主表": { "表": "demo_tea_orders", "日期列": "dt", "过滤": "is_refund = 0" },
  "维表": [ { "表": "demo_tea_store", "外键": "store_id",
              "维度": [ { "名称": "门店", "列": "name", "点查词": ["西湖店", "湖滨店"] },
                        { "名称": "城市", "列": "city" } ] } ],
  "指标": [
    { "名称": "营业额", "类型": "金额", "列": "amount", "同义词": ["流水", "销售额"] },
    { "名称": "杯数",   "类型": "数量", "列": "cups" },
    { "名称": "杯单价", "类型": "比值", "分子": "营业额", "分母": "杯数" }
  ],
  "验收": [
    { "q": "昨天营业额是多少", "value": 9828.65 },
    { "q": "近30天各门店营业额", "rows": 3 },
    { "q": "西湖店营业额是多少", "value": 12580.75 }
  ]
}
```

就这么大。这一份等价于手写 40+ 行本体 profile。

## 字段说明

### 主表(必填)
| 字段 | 说明 |
|---|---|
| 表 | 事实表名 |
| 日期列 | DATE/DATETIME 列 |
| 过滤 | 可选。业务口径,如 `is_refund = 0`;多条件用 and 连接:`status = '已完成' and amount > 0` |

### 指标(必填,≥1)
| 字段 | 说明 |
|---|---|
| 名称 | 业务名(也是提问用词) |
| 类型 | **金额/数量**=对列求和(聚合表、金额类);**次数/人数**=按列去重计数(明细表);**比值**=两个已定义指标相除 |
| 列 | 金额/数量/次数/人数 时必填(次数/人数填"去重依据列",如订单 id、用户 id) |
| 同义词 | 可选,提问变体 |
| 分子/分母 | 比值类型必填,引用其他指标名称 |

⚠️ 选型口诀:**聚合表(ADS/DWS)用 金额/数量;明细表(DWD)的"多少个/多少人"用 次数/人数。**

### 维度(可选)
| 字段 | 说明 |
|---|---|
| 名称 / 列 | 主表上的维度列 |
| 同义词 | 可选 |

### 维表(可选,星型模型)
| 字段 | 说明 |
|---|---|
| 表 / 外键 | 维表名 + 主表里的外键列(自动生成 LEFT JOIN) |
| 维度 | 该维表上的维度(名称/列/同义词) |
| 点查词 | 可选。可直接点查的取值,如 ["西湖店"]——问"西湖店营业额"即自动过滤 |

### 验收(强烈建议)
| 字段 | 说明 |
|---|---|
| q | 试问 |
| value | 期望数值(从数仓查询取锚点) |
| rows / rows_at_least | 期望分组行数(下限) |
| action / metric / metric_matched | 路由/指标/词表命中断言 |

保存上线时自动执行:**全绿才上线**;之后随时 `GET /api/ui/report/<profile>` 出验收报告。

### 节日(可选)
```json
"节日": { "周年庆": { "2026": ["2026-09-15", "2026-09-15"] } }
```

## API

- `GET /api/ui/spec/template` → 模板
- `POST /api/ui/spec/compile`(spec)→ 编译预览(profile)
- `POST /api/ui/spec/save`({spec})→ 编译+校验+保存+自动验收
